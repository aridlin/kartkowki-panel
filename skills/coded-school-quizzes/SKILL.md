name: coded-school-quizzes
description: Create or revise the user's coded math quizzes and clean class bundles in the self-hosted assessment panel, with verified keys and printable PDFs. Use for this assessment workflow, not unrelated homework.
---

Use the assessment MCP tools through the user's existing authenticated SSH transport. The panel runs on the ProLiant under `/opt/kartkowki`; production is `/kartkowki/`, and `/kartkowki/test/` has an isolated database with fictional Muppet pupils. Choose the intended environment before mutating it. Never put smoke-test pupils or grades in production.

For a new class using existing questions, use `clone_quiz_for_class`. It creates a fresh quiz identity, new codes, and clean sheets while retaining the key. To write new questions or change questions, use `propose_quiz`; select a model from `list_models` when requested, otherwise preserve the default. Supply the requested topic, difficulty, number of groups, point maxima, and requested changes. Read the result with `get_quiz_draft`. If the user asked for a draft, leave it as a draft; if they asked for a finished worksheet, validate it and use `publish_quiz_draft` for the intended class within the authorized scope. Corrected printed questions receive a new version and fresh codes so existing scans still resolve to their original key. For another correction, pass `source_draft_id` or `source_quiz_id`.

The current format is three fraction-arithmetic tasks, two works per A4 page, grids for solutions, and four inward ArUco corners per work. Final answers must be integers or mixed numbers. Compute keys with exact fractions, reject zero denominators and duplicated tasks, render-check the PDF, and decode all full Code128 values and crops before delivery. Keep actual mathematical complexity consistent with the user's supplied examples; task counts and constraints may change with a later request.

The first three barcode characters are reserved for the group number; the remaining characters identify the new quiz/work. Full codes identify work globally, while a bare group number is meaningful only within the selected quiz. Never reuse a printed code for another student or class.

Each task has a segmented main figure: three points use a triangle split by vertices to its center; four points use four squares in a square. An adjacent small square has four quarter-point segments. Two main segments plus two quarter segments means 2.5 points. Leave the removed footer instruction and “gotowa” checkbox off the papers. Empty figures do not by themselves mean a completed zero-point manual grade. The original scan remains intact; graded copies fill the figures from per-task scores.

Grade using the configured school policy, not a model-invented percentage scale. SP 263 point-scored written work uses §60(9). ZS 33 uses the relevant Technikum 6 or BS I stopnia 7 statute; the teacher explicitly resolved exactly 34% as 1 and every greater value as at least 2, with no rounding before comparison. ZS 33 grade 6 requires 100% base points and at least half of a declared bonus task; a quiz without a bonus tops out at 5. Preserve unknown student/school and uncertain readings for review. Do not infer requirements from sensitive pupil notes; use only necessary roster names and identifiers.

The panel supports Codex OAuth model selection, per-task corrections, scanner summaries ordered grade → points → pupil → quiz, manual group assignment, dark/light/system theme, and revocable password-in-link access to one cropped work. Send scanning replaces binup with local ingest and automatic routing of test barcodes. Preserve scanner locking, originals, Paperless ingestion, authentication and durable jobs. Do not submit grades to Librus; links are copied by the teacher into grade comments, and automated Librus filling is a separate future request.

Read the maintained repository's README for deployment/API details. When using Codex CLI directly with an image, put `--` before the prompt, or the image flag may consume the prompt. Do not copy OAuth credentials between computers or publish roster files, scans, databases, environment files, or tokens. Back up source and SQLite data before a deployment; verify live behavior after it.

Repeated scans with the same full barcode are versions of one work. Preserve every original and assessment; default to the newest received capture, keep older versions in history, and retain the same pupil link with newest-version resolution. A delivery retry with the same capture ID is idempotent. Send can use automatic Codex grading or explicit manual-mark reading; empty shapes mean zero only in the explicit manual mode.
